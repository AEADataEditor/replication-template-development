## Description

Converts the manuscript PDF(s) in a directory to Markdown and extracts the figures as images. The conversion is mechanical: nothing is interpreted, summarized or corrected. The `m-parse-manuscript` pipeline runs it through [31_parse_manuscript.sh](#help-31_parse_manuscript) and commits the result as `manuscript_parsed/`.

A file is taken to be the manuscript when its name is

- `PDF_Proof.PDF` (any case), or
- a journal acronym followed by the manuscript number, such as `AEJApp-2025-0453.R1_Proof_hi.pdf` or `AER-2025-0473_AO.pdf`.

Other PDFs (forms, `Data and Code Availability.pdf`, `13071-2.pdf`) are ignored.

## Usage

```bash
python3 tools/manuscript_to_markdown.py [--source-dir DIR] [--output-dir DIR] [--engine auto|marker|markitdown] [--list]
```

- `--source-dir` - Directory with the PDFs (default: current directory).
- `--output-dir` - Where the results go (default: `manuscript_parsed`). Each manuscript gets `<output-dir>/<file stem>/`, holding `<file stem>.md` and the extracted images.
- `--engine` - `marker` runs `marker_single` with OCR disabled (layout, tables, equations, figures as images). `markitdown` extracts text only: fast, no images. `auto` (default) tries marker and falls back to markitdown if marker is missing or fails.
- `--list` - Print the files that would be converted and stop.

Exit code 0 on success or when no manuscript is found; 1 if a manuscript could not be converted by any engine. A new run replaces the earlier result for the same file.

## Which converter

Measured on two 90-page proofs (PDF_Proof.PDF and an AEJ: Applied proof), without OCR:

| | markitdown 0.1.9 | marker 1.10.2 | marker 2.0.0 |
|---|---|---|---|
| Time, CPU, 8 threads | 4-47 s | 16-33 min | 30-34 s |
| Time, GPU (RTX 3060) | - | 1-2 min | 27-30 s |
| Peak memory (CPU) | 0.1-1.7 GB | 12.5 GB | 2.3 GB |
| Figures as images | none | 9 and 31 | 7 and 25 |
| Equations | broken into table fragments | LaTeX | flattened text |
| Words run together | yes (AEJ proof) | no | no |

The figures in these PDFs are vector graphics, so only marker's layout detection recovers them. Marker 2.0 gives the same output on CPU and GPU; the Bitbucket-hosted workers have no GPU. The default is marker 1.10.2, which keeps more of the tables, captions and equations; see `requirements-manuscript.txt` to switch to 2.x.

## Requirements

`pip install -r requirements-manuscript.txt` (marker and markitdown). On a machine without a GPU, install the CPU build of `torch` first (see the comment in that file).
